# 项目演示脚本

## 1. 演示前检查

- 后端、MySQL 已启动；Redis 状态已知。
- 前端通过 `npm run serve` 启动，API 代理指向当前后端。
- 使用专门的演示普通用户和管理员，不使用真实个人数据。
- 若展示真实模型/地图/天气，已获得调用授权并确认配额。
- 浏览器开发者工具、终端和配置文件中没有可见密钥、Token、密码或本机敏感路径。

## 2. 8–10 分钟主线

1. **问题与边界（45 秒）**
   - 输入不只是自然语言，而是城市、日期、人数、预算、同行类型和偏好。
   - 模型不能任意调用工具；Java 验证和白名单决定能否完成。
2. **登录和身份（45 秒）**
   - 刷新验证码，登录普通用户，展示 `/me` 对应用户。
   - 说明 Token 只存在 sessionStorage，403 不等于登录过期。
3. **偏好记忆（60 秒）**
   - 设置 interests/pace/travelMode/accommodationPreference。
   - 说明显式输入优先、可单次关闭、可清空、按用户隔离。
4. **提交杭州两日请求（90 秒）**
   - 展示结构化请求和 `useSavedPreferences`。
   - 创建后显示 PENDING/RUNNING，观察 SSE 阶段；刷新页面后仍可查询任务。
5. **行程详情（120 秒）**
   - 仅当真实任务完成时展示日期、活动、预算、warnings、metrics 和版本。
   - 指出 `numerator/denominator` 和零分母 null；缺少的路线/证据字段保持 null/空。
6. **知识库与引用（90 秒）**
   - 管理员上传带来源元数据的公开文档，展示 ACTIVE 和切片预览。
   - 说明 chunkId 白名单、城市过滤和禁用/重建索引。
7. **修正和 Trace（90 秒）**
   - 使用真实触发修正的任务；展示版本数和脱敏进度。
   - 说明最多一次结构重试、两次规则修正，每版重跑全量 Java 规则。
8. **评测与限制（60 秒）**
   - 打开本次离线报告，明确 40 条 fixture，不称为真实模型成功率。
   - 打开本次真实冒烟报告，说明它只有两个固定场景的一次运行，并展示 Redis 不可达及现存 warning；不要包装成成功率或零告警。

## 3. 失败分支

- 路线供应商失败：展示真实终态/错误码或降级行为，不口头改写成成功。
- Redis 故障：展示回源仍可用，并说明 Redis 不是事实源。
- 非管理员访问知识接口：展示 403 和普通用户会话仍有效。
- 低预算/硬约束冲突：展示 `NEEDS_ADJUSTMENT`、warnings 和版本，而不是隐藏失败。
