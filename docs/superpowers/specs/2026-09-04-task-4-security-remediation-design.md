# 任务四安全修复设计附录

## 目标与边界

本附录只修复任务四代码审阅发现的鉴权和数据一致性问题，不实现任务五及后续旅行规划能力。修复后，应用只保留 `/api/auth/**` 认证入口，所有受支持业务接口统一位于 `/api/**` JWT 边界内。

## 遗留接口下线

删除旧 `UserController` 与 `AiRecommendationsController` 的 Spring MVC 控制器实现，使 `/login`、`/captcha`、`/recommended`、`/suggest`、`/collect`、`/list`、`/route` 不再注册。选择删除而不是增加兼容开关，避免明文密码比较、全局验证码、完整 `User` 返回和客户端指定其他用户 ID 的旁路被误启用。保留仍可能被后续任务复用的实体、Mapper 和 Service，任务十五再按新契约实现前端替换。

## JWT 与请求上下文

- JWT 签发显式使用 HS256；解析器只允许 HS256，密钥仍要求 Base64 解码后至少 32 字节。
- 管理员路径判断使用去除 context path 和矩阵参数后的应用内路径，同时覆盖 `/api/admin` 与 `/api/admin/**`。
- 拦截器实现异步生命周期回调，在同步完成和异步处理开始时都清除 `CurrentUserContext`。
- `/api/auth/captcha` 响应增加禁止缓存头。

## 验证码与账号唯一性

- Redis Lua 脚本对验证码执行原子“读取并删除后比较”，无论答案正确或错误，一个 `captchaId` 都只能尝试一次。
- 全新库与旧库升级最终都使用唯一用户名索引。升级前文档要求检查重复非空用户名；发现重复时停止升级，不猜测合并。
- 登录查询移除 `LIMIT 1`，使数据库唯一约束成为身份确定性的唯一来源。
- 已升级的目标数据库先只读确认无重复用户名，再在现有备份保护下把非唯一用户名索引替换为唯一索引。

## 测试与验收

先补充会失败的测试，覆盖 HS256 固定、context path/矩阵参数管理员鉴权、异步上下文清理、验证码错误后销毁、验证码禁止缓存和遗留路由未注册。随后实施最小修复并运行任务四定向测试与完整 Maven 测试。

数据库验收继续核对七张 Agent 表、角色列、外键、关键索引、唯一用户名索引和全部用户密码 BCrypt 状态。运行验收使用 JDK 21，通过进程环境变量连接 MySQL 与 Redis；要求 `/actuator/health` 为 `UP`、验证码接口为 200、未带 Token 的 `/api/auth/me` 为 401。任何凭据都不写入仓库或日志。
